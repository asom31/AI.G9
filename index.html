Words to know

component
one part of a workflow, such as the data, the prompt, the tool or the output
data
the information you supply to the workflow, containing no personal data
prompt
the clear instruction that directs the tool on what to do with the data
tool
the AI step that carries out the task using your data and prompt
interaction
the way one component hands off to and shapes another so the workflow completes the task

Components that interact

Why is a solution not one magic step?

A structured AI solution is a set of components that interact. You supply data, you write a prompt that tells the tool what to do, the tool does the work, and you evaluate the output against the problem you defined.

The interactions are the point: a vague prompt gives the tool nothing useful to do, and messy data gives a messy output no matter how good the tool is. When you design, you specify each component and think about how a change in one ripples through the others.

Why it mattersAcross the UAE, organisations build structured AI workflows to triage messages, screen documents and plan services – always as interacting components that are tested before anyone trusts them.

Part 2 of 3

Define, then build

What has to come first?

Before building anything, a designer states the defined problem clearly – what counts as a good solution. That definition tells you what data you need, what the prompt must ask for, and what a correct output looks like.

Then you build and test: run the workflow and verify that the output actually solves the defined problem, checked against a trusted source. If it fails, you know which component to adjust because you know what each one was meant to do.

Part 3 of 3

Verify, don’t trust

Can you trust a confident output?

Check the components, not the polish

Even a confident output can be wrong, so you check the components rather than trusting how polished the result sounds. Verifying against a trusted source is what turns a good-looking answer into a solution you can stand behind.

Using the words component, data, prompt, tool and interaction correctly lets you say exactly where a problem could enter – and which component to adjust when it does.

Hands-on mission: design the four-component workflow

Away from the screen. Simulated-AI cards, so no accounts or personal data are needed.

You need: a problem menu card, component cards (data, prompt, tool, output), a simulated-AI card deck, a trusted-source reference sheet and a pencil.

  1. Choose one defined problem and write, in one line, what a good solution looks like.
  2. Specify your data component – exactly what you will supply, with no personal data.
  3. Write your prompt so the tool knows exactly what to do with the data.
  4. Place the tool card that matches your prompt and run the workflow.
  5. Record the output and note one interaction between two components.
  6. Evaluate the output against the problem and a trusted source, then tick or fix each component.
No cards?Go fully human: one student is the tool and follows the pair’s written prompt exactly, using only the supplied data, while the others evaluate the output.
Think about itIf two designers built a workflow for the same defined problem but wrote different prompts, could they both produce a correct solution? What would have to be true?
